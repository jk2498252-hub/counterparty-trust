# Counterparty Trust v0.3.1

Internal pilot release that closes a source-quality gap found when reviewing v0.3.0, and puts releases behind the owner's approval.

- **The right kind of source for each check.** A positive finding now needs the kind of source its check requires: an official register for legal identity and tax; an independent confirmation for representative authority and bank details; the client's documents plus an official record for document consistency; and something other than the supplier itself for digital identity and operations. A source labelled "Unverified" never supports a positive finding. Before this release, a single self-labelled source could mark every check Verified.
- **Standard validity for common sources.** BRS, KRA, eTIMS, county permit, PPIP, KENIC, independent calls and client documents now have standard recheck periods (for example 30 days for registry searches). They are filled in automatically, so analysts only explain departures.
- **Exceptions shown to the reviewer.** Later recheck dates, missing certificate expiries, non-standard sources and unusual categories are listed on the Review tab before a reviewer can pass the case. The QC checklist has a matching item. Dates more than three years after the check are treated as mistakes.
- **Releases need the owner's approval.** Builds still run automatically after CI passes, but publishing an update to installed apps now waits for approval on the GitHub "release" environment, and refuses to publish if that approval rule is missing.

## Upgrade

Back up first. Installed v0.2.0 and later can use **Help → Check for updates…**. Open cases whose positive findings cite only one kind of source will show what is missing on the Checks tab and need the right source before review or release. Already released reports are unchanged.

The installer remains unsigned and this is not a production-approved service.
