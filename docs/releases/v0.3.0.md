# Counterparty Trust v0.3.0

Internal pilot release adding smart workflow guidance and enforceable source validity.

- **Smart assistant:** explains outstanding case checks, expired sources, payment-date concerns and independent-review steps. Generates an internal handover draft linked to the case's evidence codes.
- **Attention queue:** surfaces active case work, source deadlines within seven days and payment dates within three days. Dashboard and assistant refresh every minute while visible, pausing when a field has focus.
- **Supplier matching:** suggests possible existing profiles during intake and in the assistant using recorded identifiers, names and domains. Staff decide whether a candidate is the exact entity; profiles are never merged automatically.
- **Source validity:** record the source's actual expiry or a justified recheck date, plus the basis. Positive findings require current examined support. Suggestions, submission, review and release recheck validity; an expiry after approval blocks release. Editing validity invalidates review and is audited.
- **Report traceability:** new frozen reports include the source-policy metadata used for the decision. Previously issued snapshots remain unchanged.

These features use local rules and recorded data. There is no connected AI model, OCR, automatic official-source retrieval, background scheduler or message delivery in this release. Findings, verification outcomes and approvals remain human decisions.

## Upgrade

Back up first and retain the backup password separately. Existing source-policy fields start empty; the app does not invent validity dates. Open cases with positive findings need an actual expiry or justified recheck date and its basis for supporting sources before review/release. Expiry includes the recorded day; a recheck is due at the start of its date, using Nairobi dates.

Download **Counterparty-Trust-Setup-0.3.0.exe** for a manual installation. **v0.2.0 and later** can use **Help → Check for updates…** or their automatic update check. **v0.1.x** requires a manual current-version installation once. Upgrades preserve the existing app-data folder and migrate its database.

The installer remains unsigned and this is not a production-approved service.
