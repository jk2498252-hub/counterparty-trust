# Counterparty Trust v0.2.1

Internal pilot maintenance release with account-security, workflow integrity and recovery repairs.

- Keeps passwords out of redirect URLs and requires replacement of initial/reset passwords before case access.
- Restricts first-admin setup on public servers; adds MFA lockouts, five-minute enrolment, existing-factor proof for replacement, session invalidation and audited operator recovery.
- Commits case/payment decisions, version changes and audits together; protects simultaneous edits, approvals and releases; removes rolled-back uploads.
- Validates Office archive structure, checks document/report integrity, and pins capture hashes in new reports.
- Separates source check dates from report issuance and shows the actual latest released snapshot/outcome.
- Adds password-encrypted desktop backups, tested restoration of older databases and safe shutdown before backup/update.
- Publishes future versioned releases automatically after main CI, a packaged Windows app check and updater-manifest verification.

Download **Counterparty-Trust-Setup-0.2.1.exe** and run it for a manual installation. Existing **v0.2.0** installations can use **Help → Check for updates…**; downloaded updates install after a clean close or restart. **v0.1.x** installations require this manual upgrade once to gain the updater. Normal upgrades preserve the existing app-data folder and migrate its database.

Back up first and retain the backup password separately. Backups newly exported by this release use `.kctbackup`; previous unencrypted backup folders remain unchanged.

The Windows installer is still unsigned. This release does not make the service production-approved. Malware quarantine/scanning, privacy/retention/access controls, source-validity/scope policy, signed distribution and deployment/legal requirements remain on the [production checklist](https://github.com/jk2498252-hub/counterparty-trust/blob/main/docs/PRODUCTION_READINESS.md).
